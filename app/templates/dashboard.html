SEA — Semantic Enterprise Architect

A System Memory for an enterprise: it turns the documents a project writes into a single knowledge graph, and then keeps that graph honest as the system it describes changes. The graph is the memory; the agents are stateless functions over it.

Gap report Go to review gate
{# ====================================================================== Part 1 — what the tool is. Shown whether or not this workspace holds anything, because a reader meeting an empty tool needs the map before the territory. ====================================================================== #}

Why it exists

An architecture document states what a system must do and how it is built. It goes stale the moment it is saved, and nothing checks it against the next project. The questions this tool answers are the ones that need both halves at once:

  • Which requirements have no architectural answer?
  • Which part of the design answers this requirement?
  • What did the architecture deliver that nobody asked for?
  • What changed since the baseline a human approved?

How it earns trust

Extraction is a model's proposal, never a fact. Every assertion carries its provenance and its confidence, and a human gate stands between the proposal and the graph — so no finding is ever built on unreviewed output.

  • Nothing is dropped silently. An output key nothing reads, a refused fact, a lost pass — each is reported rather than swallowed.
  • Absence is only evidence when extraction is COMPLETE, and the graph records its own completeness.
  • An impossible fact is refused at the write boundary, so it cannot acquire human authority later.

What each page is for

PageStageWhat it is for
Overview— This page: what the tool is, and the state of this workspace.
Ingest1 Load a requirements or architecture document. The extraction agents draft a graph; nothing is trusted until it is reviewed.
Review2 The human gate. Verify, correct, dispute or retire each assertion, singly or in bulk. Nothing downstream may run on unreviewed knowledge.
Design2 → 3 Propose a core architecture from the requirements graph and the frozen baseline. A proposal is a draft a human applies, never a write.
Changes3 Revisions and baselines: commit a snapshot, freeze it as the baseline, promote verified facts into the system baseline, diff any two states.
Reconcile4 Resolve the cross-graph references so REQ-G and ARC-G meet, instead of leaving implements_requirement pointing at a name.
Map— The whole knowledge graph, both sides, with the cross-graph references drawn. Edge labels appear on hover, so a large graph stays readable.
C45 The architecture as a C4 specification, with its well-formedness checks and Mermaid or Structurizr notation to take away.
Gaps5 What is missing: unresolved references, requirements with no answer, and the extraction completeness that decides whether absence means anything.
Quality5 ISO/IEC 25010 coverage — which quality attributes are stated, which are delivered, and which are gaps in either direction.
Ontology0 The vocabulary extraction is held to: the import chain, every class and enum, and how many instances of each this workspace actually has.
